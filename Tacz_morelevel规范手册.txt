Tacz_morelevel 规范手册
================================

位置：仓库根目录（打开本项目时即可看到本文件）
文件名：Tacz_morelevel规范手册.txt

本文件集中存放本模组的编码约定。源码里的注册类等处只保留「见本手册」的短引用，
不要再把长规范段落复制进各个 Java 文件。


一、ResourceLocation（资源 ID）
--------------------------------

统一使用：

    ResourceLocation.fromNamespaceAndPath(namespace, path)

禁止：

    new ResourceLocation(...)

说明：
- 命名空间与路径已经拆成两段时，一律用 fromNamespaceAndPath。
- 从 JSON / 配置读到的「任意 ns:path 字符串」用 ResourceLocation.tryParse(...)；
  不要对未拆分的整串 ID 调用 fromNamespaceAndPath。


二、资源文件编码
--------------------------------

- assets / data 下的 JSON、geo、animation、lang 等文本：UTF-8，不要带 BOM。
- 带 UTF-8 BOM（EF BB BF）时，GeckoLib 等可能在第 1 列解析失败并导致客户端崩溃。


三、临时测试代码
--------------------------------

- 测完即删：不要把 /tml_locate_tp、键盘脚本等永久留在正式发布包。
- 临时包名建议 temp/；合并进正式功能前删掉或迁出。


四、世界结构间距（备忘）
--------------------------------

- 不同 structure set 的 spacing/separation 只管「同类」结构，不负责跨类型互斥。
- 仓库竞技场与军事基地若贴得太近：下个版本考虑合并为同一 structure set，或拆群系 / 加互斥。


五、盔甲 / 按键效果：双 bool（优先约定）
--------------------------------

一切盔甲触发的开关型效果（夜视、隐身、隐声等）优先按双 bool 设计，不要让某一件甲
「独占通道」在脱下时强清效果（多套抢同一功能时会出 bug）。

公式：

    真正生效 = toggled（开关意图） && eligible（当前装备资格）

| 名 | 含义 | 存放建议 |
|----|------|----------|
| toggled | 玩家按键打开的意图 | 玩家侧同步/持久；或合格件上的统一 NBT 键（夜视头盔） |
| eligible | 当前是否穿合格装备/全套 | 每 tick 或换装时计算，一般不单独持久 |

规则：
- 真正生效为 true：短时刷新 MobEffect（脱装停刷即自然过期）；需要时再挂 Visibility 等。
- 真正生效为 false：停刷效果；禁止用永久 setInvisible 且无对称清理。
- 多套甲共用一条通道时：开关挂玩家（或统一键），甲只贡献 eligible（OR 多套全套判定）。
- 换套：eligible 仍真且 toggled 仍开 → 效果不断；拆套 → eligible 假 → 自动退出。
- 禁止：甲 A 脱下时「因为我是拥有者」强制 removeEffect，误伤甲 B 仍合格的情况。

现成对照：
- 夜视（ArmorNightVisionHandler）：头盔 NBT 开关；换装边沿立刻清夜视；tick 刷新。
- 隐身斗篷（StealthCloakSkill + ArmorStealthHandler）：
  胸甲 StealthCloakEnabled（无键=默认关，同夜视）；TAG_WAS_ACTIVE 边沿只清效果不改开关；
  胸甲池 t 上限 4、每 5 tick +1；
  LivingHurtEvent(HIGH) 护甲前：t−伤害&lt;0 则归满、关开关+10s冷却。
- 潜行七级套（StealthSeventhSkill + ArmorStealthSeventhHandler）：与斗篷完全独立；
  胸甲 StealthSeventhEnabled；池上限 100；破隐冷却 8s；档位 7；外观同七级防弹。


七、乘船：碰撞箱 / 走位另路 + 头部锁定冲突（待做，已标嫌疑）
--------------------------------

现象备忘：NPC 在船上走与陆地不同的一套（乘客位移由船带；枪 Goal 仍 moveTo/strafe 无效或乱探）。

头部（已查源码，与半砖不同坑）：
- 原版 Boat.positionRider → clampRotation：yBodyRot=船头；乘客 yRot 相对船 ±105°；yHeadRot=yRot。
- 我方 applyPlayerLikeView 仍任意拧头瞄敌；tickHeadTurnBodyFollow 仍跟位移；枪 Goal 无 isPassenger 判断。
- 结果：锁头与船抢朝向（扭一下弹回 / 只能船头扇区瞄 / 躯干钉在船上）。

待做规划：
- 乘船时禁用陆地 moveTo/strafe（或 navigation 停干净）。
- 乘船瞄准策略二选一或组合：接受扇区限制并停硬拧；或乘船专用瞄（在 ±105° 内锁敌）；或后写 clamp 再补一次头（慎，易抖）。
- 理清乘客 collision/Pose/眼高与射击射线起点。
- 护航 CompanionBoatSitPoseHelper 仅陆上指令坐姿，勿与战斗乘船混为一谈。

九、模拟 CPU：当前 Level 查不到实体就丢票（2026-11-04）
--------------------------------

规则（已实现）：
- 找掩体是即时请求。SimThreadCpuManager.isKnownDead 在 level.getEntity(uuid) == null
  时返回 true，与已死亡同等丢弃。
- Wait、Ready、Running 都走这条判断：清 byId 及对应队列；Running 同时 cpu.clear()。
- admitFromWait 不再把查不到的票放回 Wait 队尾。
- 不引入 submitPos、超时保留或重试。实体回来后由 AI 重新提交。
- 允许丢掉一次未执行请求。

涉及：entity/ai/simthread/SimThreadCpuManager.java。


十、虚拟弹药容器：补充判空及空列表检查（待修，2026-11-04）
--------------------------------

当前检查结果：
- 四个实体基类的 getCapability / invalidateCaps / reviveCaps 直接使用 creativeAmmoReload，
  未判空；如果在该字段初始化前触发这些方法，存在空指针风险，触发路径尚未复现。
- MobCreativeAmmoBoxHandler.getStackInSlot、MobCreativeAmmoBox.ensure、
  MobGunReloadGoal.canUse 直接取容器 get(0)，缺少容器为 null / 列表为空时的保护。
- MobCreativeAmmoBox.isAllTypeCreative 直接调用 stack.isEmpty()，不接受 null。
- 正常创建路径使用一格 NonNullList；以上属于异常或未就绪状态的防御性检查，
  不表示正常路径已经确认会传入 null 或空列表。

后续修改约定（已提出，尚未实现）：
- 弹药访问对象未初始化时，能力查询回退父类；invalidate / revive 做空值保护。
- 容器为 null 或空列表时避免 get(0) / set(0)；读取返回 ItemStack.EMPTY，
  ensure 跳过，换弹条件返回 false；物品栈为 null 时类型检查返回 false。
- 保持正常的一格创造弹药箱及换弹流程不变，不扩展为其他库存机制。

涉及：
- integration/tacz/MobCreativeAmmoBoxReloadAccess.java、MobCreativeAmmoBoxHandler.java、
  MobCreativeAmmoBox.java。
- entity/ai/MobGunReloadGoal.java。
- entity/custom/AbstractPlayerLikeSoldierEntity.java、AbstractNeutralGunNpcEntity.java、
  AbstractSlimeExperimentEntity.java。
- entity/companion/AbstractSoldierArrangeFriendEntity.java。


十一、生成装备：finalizeSpawn 打标记，乘客由 tick 补一次（2026-11-06）
--------------------------------

骑马 / 结构乘客不会走 finalizeSpawn，枪和甲会丢。

规则：
- 四个基类各有一个不进 NBT 的标记。真正执行到的 finalizeSpawn 里置 true。
- 歼灭者、战争机器、炸弹宝宝不调用 super.finalizeSpawn，在自己的生成函数里置标记。
- 标记仍为 false 时，服务端 tick 调用该类的 initializeSpawnEquipment 一次，然后置 true。
- 读档时已有皮肤标记、代际标记或装备槽物品，则视为已经生成过，不再重发。

涉及：
- AbstractPlayerLikeSoldierEntity、AbstractNeutralGunNpcEntity、AbstractSlimeExperimentEntity。
- AbstractSoldierArrangeFriendEntity。
