# 持枪占位 Goal（8 点视线）— 规划备忘

> 状态：草案，待定案后再实现。  
> 相关：Goal 层战术选点；**不**改 A* / 蹲趴双图寻路。

## 背景

- 蹲/趴双层寻路边界多，短期不优先整改编排器。
- 战斗位移改在 **Goal 层**：有目标时先选「能看见玩家」的附近点，再 `navigation.moveTo`。
- 寻路仍只负责走到选中点；姿势碰撞降级（`resolveCollidingPose`）保留作执行兜底。

## 目标流程

1. `getTarget() != null` 且主手持枪。
2. 在 NPC 附近生成 **最多 8 个候选点**（优先落在现有内外射界环上，避免纯贴身乱随机）。
3. 每个点用 **假设头部/眼高**（第一期：站立眼高；以后可加蹲/趴）对目标做 **3 条射线**。
4. 视线复用现有 API（如 `SoldierGunPassthroughSight` / 同类：眼→眼、眼→身、穿障规则等），避免另起炉灶。
5. 任一候选通过 → `moveTo` 该点；到点后 STRAFE / 开火。
6. 全部失败 → **回退**：玩家位置，或玩家附近再采点（冲脸风险见开放问题）。
7. **重算冷却**（约 1–2s，或丢视线后再刷），避免每 tick 换点抽风。

## 候选点过滤

- 脚下可站、非虚空；可选简单 walkable / 实心顶面。
- 与目标距离落在攻击半径合理区间（对齐现有 `attackRadius` 内外环思想）。

## 与现有系统关系

| 系统 | 关系 |
|------|------|
| A* / `SoldierWalkNodeEvaluator` | 只负责走到选中点；本方案不改认格 |
| `PathNavigation` / `PathNavigationRegion` | 照旧；目标改为候选点或回退点 |
| `setPose` / `resolveCollidingPose` | 保留；选点射线以后可按蹲/趴眼高 |
| 趴压跳 / 站趴双图寻路 | **另案**，本阶段不做 |
| `MobGunRanged*AttackGoal` | 用本占位替换，或包一层「先选点再原逻辑」 |
| `SoldierMoveControl` STRAFE | 到点后仍可走位；不重做 STRAFE 小跳 |

## 非目标（本阶段不做）

- 趴洞直线建图、站/趴双图拼接。
- STRAFE 被挡小跳。
- 为占位单独重写整份 WalkNodeEvaluator 方块类型表。

## 验收草稿

- [ ] 掩体后：会挪到 8 点之一能开枪，而不是只会 STRAFE 原地丢视线。
- [ ] 无可用点：回退行为可接受、不每 tick 抖动。
- [ ] 有冷却：不会频繁换导航目标。
- [ ] 与现有穿障/视线规则一致（不「看得见却开不了」或相反）。

## 开放问题

1. 回退用玩家脚底，还是玩家周围再采一圈？
2. 3 条射线具体复用哪几个现有方法 / 类？
3. 第一期是否就加蹲眼高采样，还是只站立眼高？
4. 8 点几何：固定八角环，还是射界环上随机抖动？
